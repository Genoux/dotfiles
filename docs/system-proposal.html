01 / The recommendation

Make the manager smaller.

The strongest parts are already in place: modular Hyprland Lua, a single Quickshell desktop, Stow packages, static package manifests, and Matugen. The complexity comes from overlapping control paths and promises the tooling does not reliably keep.

Keep / the foundation

Your desktop stays yours.

Keep Hyprland, Quickshell, Awww, Matugen, Stow, native Bluetooth, capture, media, notifications, and session restore. Preserve the existing visual language and keyboard workflow.

Remove / the second manager

End the GUI conversion.

Retire the experimental Workspace Settings app and its prompt bridge. Keep one small Gum menu that calls the same commands you can run in a terminal.

Repair / the contract

Make success mean success.

Unify setup runners, report unknown and skipped states honestly, stop automatic conflict removal, and replace the current rollback claim with explicit config backups and reliable retries.

Why this direction

A graphical package manager must reproduce terminal prompts, authentication, cancellation, logs, and recovery. This experiment adds all of that while still retaining the original TUI. Removing it eliminates a second implementation of system administration.

The manager’s own tests pass. Removing it is a scope decision; this review does not claim to have reproduced every earlier GUI failure.

02 / The working flow

Three moments. Clear boundaries.

A daily action should never require understanding the installer. The following is the proposed behavior; new command names are design targets, not commands already implemented.

The bar controls your session.

Volume, Bluetooth, network, media, clipboard, capture, and power remain direct controls. One “System” entry opens a compact terminal menu when administration is needed.

01Choose an action

Use a bar control, the launcher, or a keybinding.

02Use its owner

Native shell service for controls; Lua actions for window behavior.

03Show the result

Update the control or display a useful error.

04Keep working

No setup wizard or full-install action in the daily menu.

Suggested System menu: Health · Update · Packages · Cleanup · Advanced. Keep power controls in the existing power menu. Advanced links to configuration and setup commands.

One visible update workflow.

Make dotfiles update the simple entry point, with dotfiles packages update retained as an alias. A normal terminal handles package-manager questions directly.

01Check

Take one operation lock; check free space and package-manager availability.

02Review & update

Run the official/AUR update. Keep dependency conflicts visible for a decision.

03Apply known changes

Run only pending, explicit migration steps after success.

04Report

Show failures, pending custom builds, config merges, and restart needs.

Keep private PKGBUILD builds explicit. Repo changes are reviewed locally; do not automatically pull over a dirty dotfiles checkout. “No updates,” “not checked,” and “check failed” must be different states.

A linear installer for an installed Arch system.

./install.sh prepares the desktop after Arch is installed. Keep a readable phase log and retry failed work. Separate a usable desktop from optional private applications.

01Inspect & plan

Check prerequisites, detect hardware, and show the intended packages and changes.

02Install packages

One main official upgrade/install transaction, then AUR; bootstrap only when required.

03Apply configuration

Back up conflicts, Stow, run one canonical system setup, generate theme assets.

04Verify & finish

Check the selected manifests and links. Report private apps as installed or pending.

Keep official/AUR/custom and hardware manifests separate. Personal apps and development integrations get an explicit optional completion step. A second run should produce no unnecessary changes. Validate fresh install and resume in a disposable VM.

Quickshell → interaction

Display state and provide everyday controls. Administrative work opens the CLI.

dotfiles → administration

One implementation for install, update, configuration, health, and cleanup.

UWSM + systemd → lifecycle

Own the graphical target and frequent daemons; avoid competing start/stop paths.

Hyprland → session behavior

Keep Lua actions, the Quickshell launch, session restore, and short login tasks.

03 / What needs attention

Fix trust before adding features.

These findings come from source inspection, a test run, and read-only checks on this machine. Impact is described conservatively: dangerous branches were not executed.

01

Updates can remove packages without dependency checks.

After an update fails, the script extracts conflicts from its log and runs pacman -Rdd --noconfirm. If the retry fails, the machine can be left with missing dependencies. Stop at the conflict and let the package manager present the decision.

Evidence & proposed correction

lib/package/update.sh:201–215 contains the forced removal and retry. This is a confirmed code path, not a failure reproduced on the live machine.

The same updater moves ~/.npmrc aside at lines 193–199 and restores it only on the normal path. Use the existing environment override without moving the file, or guarantee restoration on interruption. A single workflow lock should cover preflight, cache work, package transactions, and post-update reporting.

High priority
02

The advertised rollback cannot restore the system.

Snapshots contain package names and symlink paths. Rollback removes newer packages and links; it cannot restore upgraded versions or previous file contents. The separate “atomic” layer is not connected to normal configuration linking.

Evidence & proposed correction

lib/install-state.sh:145–243 records inventories and removes their differences. This can include packages installed independently after the snapshot. lib/atomic.sh:62 defines staging, but no external caller uses it; install/config/stow.sh:16 links directly.

install.sh:249–253 marks installation complete before the nominal atomic commit. Keep useful phase tracking and conflict backups. Retire the unsafe phase rollback and unused transaction machinery. Describe package changes honestly as non-transactional. This machine uses ext4; a Btrfs snapshot design would be a separate project.

High priority
03

Setup and status disagree about what “applied” means.

The daily system command runs ten scripts; the installer runs eighteen, with different membership. Daily apply can continue after failures. Status shows success for scripts that have no check at all.

Evidence & proposed correction

Compare lib/system.sh:44–59 with install/system/setup.sh:38–56. The daily path omits items including zram, keyd, PAM, and hardware post-install work. lib/system.sh:78–84,103–111 explicitly assumes success when no status check exists.

Use one setup runner from both entry points, propagate failures, and expose measured states: healthy, needs attention, unknown, skipped. Health should inspect files and services without sourcing scripts that apply settings. Keep the first version small: missing selected packages, broken links, failed units, theme assets, and Hyprland errors.

High priority
04

Recovery and resume contain outdated integration.

Recovery edits a legacy conf/autostart.conf that is not the active Lua configuration. Resume passes a string to the DPMS dispatcher where the current API expects a table, then hides any error.

Evidence & proposed correction

lib/recovery.sh:57–67,103–122 changes the obsolete path and relaunches Quickshell directly. stow/scripts/.local/bin/system-lock-after-sleep:34 calls hl.dsp.dpms("on"). Both the installed sample /usr/share/hypr/hypridle.conf and the current dispatcher reference use a table argument.

Fix the call shape against installed Hyprland 0.56.2 and verify on a controlled suspend/resume. Replace generic recovery modes with targeted health, config relink, and a session-aware shell restart. Preserve the healthy-lock guard; broad process killing must not take down the lock screen.

High priority
05

Old and new desktop pieces coexist.

The bar and Super+D still open the TUI, while a second desktop entry opens the experimental manager. A retired Walker autostart fails at login. The update badge reads a state file last modified in May, with no current writer found.

Evidence & proposed correction

bar/widgets/Dotfiles.qml:11 → config/ShellActions.qml:66 → hypr/actions/launchers.lua:12 → launch-dotfiles-menu. Separately, workspace-manager.desktop launches QML. All Quickshell-relative paths here are under stow/quickshell/.config/quickshell/.

Live evidence: ~/.config/autostart/walker-service.desktop invokes an absent Walker executable; its generated user unit is failed. services/Dotfiles.qml:10–16 reads updates.state; the live file is dated May 27 and says false. No maintained writer was found in the repository or inspected local scripts/units.

Remove the experimental surface and duplicate launch wrapper. Retire obsolete user autostarts through a small, idempotent migration. Remove the stale update indicator until a real checker exists. Inventory old Elephant config, swaync/Waybar manifests, and dangling compatibility symlinks before removing their known obsolete entries.

Simplify
06

Theme and session settings have competing owners.

The GTK installer changes the selected theme, but Hyprland exports a fixed GTK_THEME=MacTahoe-Dark. UWSM already owns the graphical session while Hyprland also manually starts and stops its services.

Evidence & proposed correction

Theme selection: lib/gtk.sh:263–280 versus stow/hypr/.config/hypr/env.lua:45. Uninstall at lib/gtk.sh:299–366 also leaves active theme/cursor settings behind. Let theme selection own the state; reset to existing assets before uninstall.

Lifecycle: autostart.lua:29–40,52–58 duplicates service handling already expressed by graphical-session units. Runtime confirms both UWSM's compositor service and graphical-session.target are active. Use UWSM's lifecycle model; validate environment readiness, portals, relogin, and shutdown before removing manual handling. Keep Quickshell's existing Hyprland launch ownership.

Move default-browser and window-button setters out of every login and into setup. Preserve the Awww → Matugen wallpaper path and avoid restarting Quickshell for theme changes.

Unify
07

Package reporting overstates completeness.

Private apps can be skipped for missing GitHub authentication while their install phase is marked complete. Package status calls explicit packages outside two manifests “orphaned,” including legitimate hardware and custom packages.

Evidence & proposed correction

lib/package/custom.sh:38–40,104–106 skips unauthenticated builds with success. install.sh:229 then completes the phase. lib/package/verify.sh:107 verifies a limited core, not the entire selected system. lib/package/status.sh:101–134 labels untracked explicit packages as orphaned.

Report “desktop ready; personal apps pending” and keep a retryable optional step. Include the selected hardware manifests and an explicit mapping for custom package names in coverage checks. “Untracked” must remain separate from real package-manager orphans. Keep Flow, Frigate, and Idleon in the custom-build path.

Preflight also performs a full upgrade at lib/package/preflight.sh:225, followed by another at lib/package/install-official.sh:36. Consolidate the normal path; do not replace this with a partial-upgrade pattern.

Correct
08

The style reference belongs behind a developer entry.

Remove the Components button from the bar. Keep the design guide and visual reference for agents. The gallery is currently instantiated per screen and scans icons at startup even when it is never opened.

Evidence & proposed correction

bar/Bar.qml:165–169 exposes the button. shell.qml:94–101 creates gallery windows; debug/ComponentGalleryWindow.qml:729–731 runs the icon scan immediately.

Keep DESIGN.md, the shared tokens/components, and the components IPC entry. Make the visual gallery load on request. This removes development UI from daily use without losing a useful visual verification tool.

05 / Inspiration, with restraint

Borrow Omarchy's boundaries.

Research used the current quattro branch, checked September 17. Today's Omarchy includes a packaged distribution, a shell plugin system, and extensive update machinery. Copying that entire structure would exceed the needs of these personal dotfiles.

Borrow / clear entry points

One public command.

Omarchy routes user commands through one CLI; its menu wrapper delegates to the shell. Apply that principle with the existing dotfiles command and a thin menu.

CLI source ↗ · Menu source ↗

Borrow / visible maintenance

Own the whole update.

Its update flow coordinates a lock, checks, logs, migrations, and restart reporting. The bar opens an update terminal. Use that pattern at a much smaller scale here.

Update design ↗

Borrow / separate setup scopes

System, user, first login.

Omarchy separates privileged system/hardware setup from user finalization. Make those boundaries explicit in the current installer while retaining Stow.

Installation structure ↗

Deliberate limits

No new shell, ISO, plugin framework, package-manager guard, release channels, or mandatory filesystem conversion. A small migration directory is enough for known one-time cleanup. Keep existing leaf scripts wherever they have a clear owner.

06 / Delivery sequence

Small changes. Verifiable results.

Four reviewable batches. Each leaves a usable system and reduces the uncertainty of the next. No whole-desktop rewrite.

FIRST / RELIABILITYFix the dangerous edges

Repair update, status, and resume.

Stop forced conflict removal; preserve npm configuration on interruption; correct the DPMS call; propagate system-apply failures; report unknown status honestly. Disable the unsupported rollback entry until its replacement is ready.

Done when: stubbed failures return failure; Ctrl+C preserves user config; no update branch uses forced dependency removal; controlled suspend/resume works.
SECOND / SUBTRACTIONRetire the experiment

One manager, a quieter bar.

Remove the experimental manager end-to-end. Remove the Components button and orphaned badge. Consolidate launchers. Add explicit cleanup for retired Walker autostart and verified obsolete files; keep the design reference available on demand.

Done when: one desktop entry, bar button, and keybinding open the same TUI; no broken Stow links or retired-manager references; shell and lock still load.
THIRD / CONVERGENCEMake setup repeatable

One installer and one system runner.

Unify setup lists, reduce duplicate upgrade transactions, separate optional personal completion, and replace unused atomic machinery with direct backups and phase retry. Update INSTALLATION.md to describe actual behavior.

Done when: a fresh Arch VM installs successfully; rerun is quiet; interrupted phases resume; missing GitHub login leaves a clear pending state; selected hardware is verified.
FOURTH / POLISHAlign owners and reduce work

Finish the unified system.

Give session services one lifecycle owner, make theme selection authoritative, load developer UI lazily, and fix the stale test fixture. Add a lightweight automated check for shell syntax, existing tests, and obsolete references.

Done when: relogin has no retired-service failure; screen sharing, lock, restore, and theme switching work; all tests pass; idle polling has a measured purpose.
Desired end state

You know where to go: the bar for your session, dotfiles for maintenance, and install.sh for a new machine. Each action has one implementation and reports what actually happened.
